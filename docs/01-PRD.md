# 01. PRD — 장보고 (JangBogo)

## 1. 한 줄 정의

가맹점의 상품 목록을 **에이전트가 결제할 수 있는 헤드리스 상점(x402 엔드포인트)**으로 5분 만에 변환하고,
들어오는 구매 에이전트의 **AP2 mandate를 검증해 안전하게 파는** 에이전트 커머스 게이트웨이.

## 2. 타깃

| 구분 | 대상 | 페인포인트 |
|---|---|---|
| 1차 (판매자) | 국내 소상공인·온라인 셀러 (VAN/PG 가맹점 33만+) | 에이전트 고객을 받을 방법이 없음 — 쇼핑몰 UI는 사람용, 카드 결제는 본인인증 필수 |
| 2차 (구매자) | 자율 조달이 필요한 사업자 (카페·식당·사무실의 반복 소모품 구매) | 매주 견적 비교→발주→결제 반복 노동 |
| 3차 (인프라) | PG/VAN/카드사 | 에이전트 결제 트래픽을 수용할 가맹점측 어댑터·신뢰 통제 부재 |

## 3. 문제 정의

1. **판매 접점 부재**: 에이전트 커머스 프로토콜(x402·AP2·ACP)은 빠르게 표준화 중이나, 일반 가맹점이 올라탈 방법이 없다. 쇼핑몰을 API 상점으로 바꾸는 데 개발자가 필요하다.
2. **신뢰 부재**: 자율 결제가 열리는 순간 가맹점의 질문은 "이 에이전트를 믿어도 되나"다. 위임 증명 없는 에이전트 주문은 분쟁·자금세탁 리스크다.
3. **결제 레일 부적합**: 에이전트는 카드를 쓸 수 없다(3DS·본인인증·차지백 전제 = 사람용 설계). 해외 구매 에이전트는 더더욱.

## 4. 솔루션

### 4-1. 머천트 온보딩 (5분)
- 상품명·가격(KRW)·재고·카테고리 입력(또는 붙여넣기) → 즉시 발급:
  - `GET /api/m/{id}/catalog` — 기계가 읽는 상품 카탈로그 (JSON)
  - `POST /api/m/{id}/quote` — A2A 메시지 구조의 견적 응답 (머천트 에이전트가 응답)
  - `POST /api/m/{id}/buy` — x402 결제 플로우 (402 → USDC 지불 → 검증 → 주문 확정)
- KRW 가격은 고정 환율(데모)로 USDC 병기.

### 4-2. 신뢰 레이어 — 판매자측 mandate 검증 (핵심 차별점)
- 구매 에이전트는 주문 시 **AP2 스타일 Intent Mandate**(사람이 서명한 위임장: 예산·카테고리 범위·만료)와 **Cart Mandate**(에이전트가 서명한 장바구니)를 제출.
- 가맹점 서버가 결정론적으로 검증: ① 서명 유효 ② 만료 전 ③ 카테고리 범위 내 ④ 누적 지출 + 이번 주문 ≤ 예산 ⑤ 온체인 지불 금액 = 주문 금액.
- 하나라도 실패 → 결제 거절(주문 불성립). LLM 판단 개입 없음 → 프롬프트 인젝션으로 뚫리지 않음 (arXiv 논거 체인).

### 4-3. 자율 구매 에이전트 (데모용 레퍼런스 구현)
- 입력: 조달 목표(예: "원두 5kg 확보") + mandate(예산 50 USDC, 카테고리 '식자재', 7일 만료).
- 동작: 등록 가맹점 전체에 견적 요청 → 비교·선택(Gemini 사유 생성, 실패 시 결정론적 폴백) → devnet USDC 전송 → X-PAYMENT 재시도 → 영수증 수취. **전 과정 사람 승인 0회.**
- 전 단계 로그를 대시보드에 실시간 스트리밍.

### 4-4. 정산 대시보드
- 주문별: 트랜잭션 해시(익스플로러 링크) · 지불 에이전트 · mandate 잔여 예산.
- 정산: USDC 수취액 → 수수료 0.5% 차감 → 원화 환산 정산 예정액 (오프램프 시뮬레이션, 데모 고지).

## 5. 수익모델 (PPT 필수 항목)

1. **거래 수수료**: 결제액의 0.5% (카드 가맹 수수료 대비 1/3~1/6)
2. **SaaS 구독**: 정산 리포트·재고 연동·다중 지점 (월 29,000원)
3. **확장**: 온체인 매출 이력 기반 **선정산(팩토링)** 수수료 — KG파이낸셜 신사업 정합

## 6. 왜 온체인(솔라나)인가

- 에이전트는 카드 결제 불가(본인인증 루프에 사람이 없음) → 기계용 결제 레일 필연
- 해외 에이전트 고객: 카드 수수료 ~3.5%+환전 vs USDC ~$0.0001, 차지백 없음
- ~400ms 확정, 24/7, 정산 D+0 (카드 D+2~7)
- mandate·영수증의 부인 불가능성 — 분쟁 책임소재 판별

## 7. 스코프

| 구분 | 포함 | 제외 (정직 고지) |
|---|---|---|
| 결제 | x402 플로우 자체 구현(스펙 준거), devnet mock USDC | mainnet, 실USDC, pay.sh 실연동(호환 설계만) |
| mandate | AP2 구조 준거(Intent/Cart, ed25519 서명) | SD-JWT VC 완전 구현 |
| A2A | 메시지 구조 차용한 견적 교환 | A2A 풀스펙(태스크 라이프사이클) |
| LLM | Gemini 선택적(키 있으면), 결정론 폴백 | — |
| 정산 | 원화 환산 시뮬레이션 | 실제 오프램프 |

## 8. 성공 기준 (데모 기준)

1. 온보딩→엔드포인트 발급까지 5분 내 시연 가능
2. 자율 구매 1사이클(견적 3건 비교→결제→영수증)이 devnet 실트랜잭션으로 완주
3. mandate 위반 3종(예산 초과·만료·범위 밖)이 실제로 거절되는 네거티브 데모
4. 대시보드에서 tx 해시 클릭 → Solana Explorer 확인
